# 架构说明

```text
Vue 3 管理端 / 响应式 H5
          │ HTTP / JSON
Spring Security → Controller → Service → Spring Data JPA → MySQL 8
                                  │
预约状态机 / 访客档案 / 访客证 / 门禁事件 / 通知任务 / 风险预警 / 操作审计
```

当前版本以单体分层架构保证易运行与易理解：

- `Appointment` 承载预约、审批、通行码、签到和离场状态。
- `ApprovalTask` 独立承载审批阶段、责任人、SLA、决策人和审批意见，避免把审批证据压缩在预约状态字段内。
- `VisitorProfile` 承载访客档案、身份核验与黑名单状态。
- `SiteResource` 承载接待人、访问区域和门禁点。
- `RiskAlert` 承载异常上报、责任人和处置留痕。
- `SystemSetting` 以键值形式持久化园区、审批、通行、通知和留存配置。
- `AuditLog` 记录模块、操作、业务编号、操作者、结果说明和时间，供管理员追溯关键变更。
- `VisitorBadge` 维护实体访客证从库存到发放、归还、自动回收和挂失的生命周期，并以乐观锁保护并发操作。
- `GateAccessEvent` 将允许和拒绝的入场/离场决策统一持久化，为防重复通行和事后追踪保留原始证据。
- `NotificationTask` 作为轻量可靠消息任务箱，保存渠道、模板、接收人、尝试次数、错误和重试时间。
- `VmsManagementService` 统一执行业务状态校验。
- `EnterpriseFieldService` 执行现场准入、访客证闭环、通知派发和合规留存预检。
- `VisitRiskService` 与 `EvacuationAccountabilityService` 提供可解释的风控与应急规则。

生产化时建议集成权威身份证件核验、门禁控制器、访客终端、隐私数据加密、照片留存策略和消息渠道。社区源码版已提供人工身份核验、凭证校验和应用层操作审计；硬件通行事件、真实证件服务及第三方消息能力保留集成位置。

## 企业管控链路

预约写入时先执行黑名单与时段容量校验，再根据客户端请求号完成幂等判定。每条新预约生成接待人审批任务；受限区域或多人来访在接待人确认后追加安保复核任务，只有管理员角色能够完成该阶段。审批任务独立保存 SLA 截止时间和决策证据，预约实体使用乐观锁防止并发覆盖。

在园巡检按预约日期与结束时段计算预计离场时间，对超时记录生成待处理预警，并通过“预警类型 + 预约编号 + 待处理状态”避免重复告警。所有预约、审批、巡检、名单和配置操作继续写入统一审计日志。

## 现场执行与消息链路

审批完成后，前台可将可用访客证绑定到预约。闸机或边缘网关通过统一事件接口上报预约编号、门禁点和方向；服务端在同一事务中检查黑名单和预约状态，更新到访/离场状态，记录通行决定，并在离场时自动回收已绑定访客证。重复入场与重复离场不会修改业务状态，但会留下拒绝事件。

预约关键节点不会直接调用外部消息服务，而是先写入 `NotificationTask`。派发器成功后记录发送时间；外部适配器未配置或执行失败时保存错误、尝试次数和下次重试时间。该模式让业务事务与第三方消息可用性解耦，也方便部署方替换企业微信、短信或内部消息总线。

数据留存预检只计算超出保留周期的访客档案和审计日志数量，不实施删除。生产环境应在法务确认、审批、备份和匿名化策略完成后，再扩展为受控清理任务。
